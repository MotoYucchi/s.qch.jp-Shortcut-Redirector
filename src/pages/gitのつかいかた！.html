💡 よく使う9つのGitコマンド

実際の開発で9割以上使うのは、この9つのコマンドです。やさしく解説します！

コピー

1. git clone <リポジトリ名>

ネット上のプロジェクトを自分のPCに丸ごとダウンロードしてくるコマンドです。新しくプロジェクトに参加するときに「最初に一度だけ」使います。

使用例（GitHubからプロジェクトを持ってくる）: $ git clone https://github.com/user/my-app.git
例え話でイメージ！

GitHubというネットの本棚から、自分の手元に本（プログラム）を1冊買ってきて手元に置くイメージです。

同期・取得

2. git pull origin <ブランチ名>

GitHub（リモート倉庫）にある最新のプログラムを自分のPCにダウンロードして、今の作業スペースに自動合流（マージ）させるコマンドです。チームメンバーが追加したコードを自分の手元に同期する際に毎日使います。

使用例（本番用コードの最新状態を取り込む）: $ git pull origin main
作業を始める前に打つ！

朝、PCを開いて仕事を始める前に必ず `git pull` を打つ習慣をつけましょう。古いコードの上から書き進めてしまうトラブル（競合）を未然に防げます。

連携

3. git remote add origin <URL>

「自分のPC」と border 「GitHub上の空っぽの倉庫」をヒモ付けるコマンドです。イチから自分で作ったアプリを、初めてGitHubに登録するときにだけ使います。

使用例: $ git remote add origin https://github.com/user/new-app.git
ちなみに！

「origin(オリジン)」は単なる「あだ名」です。長いGitHubのURLを毎回書くのは大変なので、「origin」というニックネームで登録しています。

分岐

4. git branch

ブランチ（枝分かれした歴史）を確認・新規作成するコマンドです。共同開発では「本番用ブランチ（mainやmaster）」を汚さないよう、自分の「作業用ブランチ」を作って進めるのが鉄則です！

使用例（一覧を表示 & 新規追加）:
$ git branch # 一覧を表示。現在地に * が付きます $ git branch my-feature # "my-feature"という作業ブランチを作る
例え話でイメージ！

元々の本番用ノートをコピーして、「実験用の下書き用紙」を新しく1枚ちぎって用意するイメージです。

状況

5. git status

「今、どのファイルを書き換えたっけ？」を確認するコマンドです。困ったらとりあえず打つコマンドです。書き換えたファイルが赤や緑の文字で分かりやすく表示されます。

使用例: $ git status
プロの超必須呪文

プロのエンジニアも「一回何か書いたら git status」「コミットする前に git status」というように、1日に何十回も打っています。

準備

6. git add .

変更されたすべてのファイルをダンボール（ステージ）に入れるコマンドです。最後の 「 . （ドット）」 は「今いるフォルダの全ファイル」という意味。特定のファイルだけを指定したい時は `git add index.html` のように指定も可能です。

使用例（全ての変更をステージに載せる）: $ git add .
ドットをお忘れなく！

初心者がよく「git add」だけでエンターを押してエラーになります。最後の半角スペース ＋ ドット「 . 」を必ず忘れないようにしましょう。

確認

7. git diff --staged

ダンボール（ステージ）に入っている変更箇所を画面で確認するコマンドです。自分がこれからコミット（保存）しようとしている変更に、余計なテスト用コードなどが残っていないか確認できます。

使用例: $ git diff --staged
通常の git diff との違い

`git diff` は「まだダンボールに入れていない変更」を見せます。`--staged` をつけると「ダンボールに入った中身」を見せます。

記録

8. git commit -m "<メッセージ>"

ダンボールのフタをして、「〇〇を修正したよ」と一言メッセージ（伝票）をつけて歴史に記録する（セーブする）コマンドです。

使用例: $ git commit -m "ログインボタンのデザイン崩れを修正"
初心者キラーの罠

末尾 of `-m "メッセージ"` を書き忘れると、黒いエディタ画面(Vim)が立ち上がり戻れなくなります。焦らず :q! と打ち込みエンターで脱出できます。

アップロード

9. git push origin <ブランチ名>

PC内にコミット（保存）されたあなたの履歴データを、GitHub（ネットの巨大倉庫）にアップロードして送信するコマンドです。

使用例（自分の作業ブランチをGitHubへ送る）: $ git push origin my-feature
例え話でイメージ！

自宅で綺麗にパッケージした商品を、運送トラックに載せて本社のネット物流倉庫（GitHub）へ一斉に届ける最終段階です！

🏃‍♂️ 朝から夜まで！毎日の仕事の流れシミュレーション

1. 朝：出勤して準備

まずは最新のプロジェクト状態をダウンロード（pull）、または新しい実験用用紙（ブランチ）を作ります。

$ git checkout main
$ git pull # 最新をダウンロード
$ git checkout -b feat-login # 新機能ブランチ作成

2. 昼：作業＆セーブ

一生懸命コードを書きます。キリが良くなったら、こまめに「ダンボールに詰めて、セーブ」をします。

# 〜〜 画面作成・バグ修正 〜〜
$ git status # 状況確認
$ git add . # 箱詰め
$ git commit -m "ログイン画面作成"

3. 夜：GitHubに発送して帰宅

今日の成果をすべてGitHub上にアップロード！明日会社PCが壊れても、GitHubにあるので安心です。

$ git status # 最終確認
$ git push origin feat-login # 発送！
# おつかれさまでした！🎉
